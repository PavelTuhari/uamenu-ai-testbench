# 8. Установка UAMenu: папка рядом с UnaDesktop, и почему `cantina.ini` главный

Касса не имеет установщика. Она **разворачивается копированием папки**,
и всё её поведение определяется одним файлом в этой папке —
`cantina.ini`. Из этого следуют и правила размещения, и правила
обращения с файлом.

## 8.1 Где лежит касса

На рабочих местах владельца касса стоит **отдельной папкой рядом с
бэк-офисным приложением UnaDesktop**, в одном родительском каталоге:

```
C:\UNA\
├── UnaDesktop\        бэк-офис (приложение владельца, ставится отдельно)
└── UAMenu\            касса: этот комплект разворачивает именно её
    ├── UAMenu.exe
    ├── cantina.ini
    ├── selftest.ini
    ├── *.dll
    └── ...
```

Почему именно так, а не иначе:

| Правило | Почему |
|---|---|
| **Рядом**, а не внутри `UnaDesktop` | обновления UnaDesktop заменяют содержимое своей папки целиком; касса внутри неё будет затёрта или подхватит чужие DLL |
| **Своя папка**, не `Program Files` | касса пишет рядом с exe журналы, чеки виртуального принтера, снимки прогона, `license.state`; в `Program Files` под UAC запись уходит в VirtualStore и файлы «теряются» |
| **Локальный диск**, латинский путь без пробелов | DLL фискальных принтеров и 32-битный клиент Oracle грузятся по пути; сетевой диск и кириллица в пути давали сбои |
| **Один `cantina.ini` на папку** | касса читает файл с этим именем; десятки `cantina_<магазин>.ini` рядом с exe у владельца — его архив вариантов, касса их не трогает |
| **Тот же `TNS_ADMIN`, что у UnaDesktop** | оба приложения ходят в одну базу по одному `tnsnames.ora`; имя в `Server=` кассы и имя в UnaDesktop совпадают, и база переключается в одном месте |

Касса **32-битная** (Win32) и к Oracle ходит через OCI: Oracle Home
выбирается в окне входа и запоминается в `OraHome=` ini. Значит рядом с
64-битным Instant Client для Python (шаг 1.2) нужен **32-битный**
клиент для кассы, с тем же `tnsnames.ora` через общий `TNS_ADMIN`.

## 8.2 Что должно лежать в папке

Содержимое папки — из каталога сборки владельца `Win32\Debug`, но не
всё подряд: там же лежат объектные файлы, резервные копии и результаты
прошлых прогонов. Переносится:

| Что | Зачем |
|---|---|
| `UAMenu.exe` | касса |
| `cantina.ini` | настройки; **готовится по шагу 3**, не копируется чужая |
| `selftest.ini` | сценарий автопрогона, если нужен акт без рук (шаг 3.3) |
| `*.dll` рядом с exe | драйверы фискальных принтеров (`ElicomFP.dll`, `FiscPrnDLL.dll`, `rti1000.dll`, `IKC_E260T*.dll` и прочие), архиватор `DelZip192.dll`, весы `un4s_*.dll`, обвязка .NET (`System.*.dll`, `RTI*.dll`) — без них касса падает при первом обращении к устройству, а не при старте |
| `Fonts_\` | шрифты чека |
| `ServerPOS\`, `Server_FP\`, `Server_PaymentApbQR\` | вспомогательные службы: лояльность, сервер фискального принтера, оплата QR; нужны, если соответствующие интеграции включены в ini |
| `Sounds\`, `Templates\`, `Advertising\`, `ru\` | звуки, шаблоны печати, рекламный экран, ресурсы языка |

Касса **сама создаёт** при работе: `Log\`, `VirtualCheckPrinter\`,
`SelfTest\`, `FiscalNotes\`, `BackupLogDir\`, `license.log`,
`license.state`, `APILog.txt`. Их из папки владельца не переносить —
это его история.

Не переносить: `*.obj`, `*.tds`, `*.pch`, `*.#*`, `__recovery\`,
`SelfTest*\`, `cantina_*.ini`, `*.before-selftest`.

Проверка папки после копирования, из неё самой:

```bat
dir UAMenu.exe cantina.ini *.dll Fonts_ ServerPOS
python -m pypos secrets check cantina.ini
```

## 8.3 Как касса ищет `cantina.ini`

Порядок жёсткий, и он объясняет почти все случаи «касса читает не то»:

1. Переменная окружения **`UAMENU_INI`** — путь к каталогу с завершающим
   `\`; если задана и файл там есть, берётся он.
2. **Каталог `UAMenu.exe`** — обычный случай.
3. **`%WinDir%`** (`C:\Windows\cantina.ini`) — наследие старых установок.

Отсюда три правила стенда:

* `UAMENU_INI` на машине быть **не должно**, если вы не задали её
  сознательно; проверить: `set UAMENU_INI`.
* В `C:\Windows` файла `cantina.ini` быть **не должно**: если касса
  запущена из папки без ini (ошиблись папкой), она молча возьмёт
  виндовый и войдёт не в ту базу.
* Две папки кассы на одной машине — две разные `cantina.ini`, и
  `UAMENU_INI` не задана. Иначе обе читают одну.

## 8.4 Почему `cantina.ini` — главный файл

Это **не** «ещё один конфиг». Это паспорт кассы и её контракт с базой:

* **Личность кассы.** `PosID` определяет нумерацию чеков, смены,
  Z-отчёты и принадлежность продаж. Касса с чужим `PosID`, вошедшая в
  рабочую схему, пишет продажи **от имени чужой кассы** и ломает ей
  нумерацию. На стенде `PosID` только тот, что выдал владелец.
* **Адрес базы.** `Server`, `Schema`, `OraHome` — куда и как входим.
  Ошибка здесь — вход в боевую базу вместо стендовой.
* **Железо и деньги.** `FiscalPrinter` и ключи интеграций: при
  `FiscalPrinter` не равном `VirtualFP` касса попытается печатать на
  **настоящем** фискальном принтере, а ключи MIA / POS API / BPAY ведут
  к **настоящим** платёжным службам. Чужой `cantina_<магазин>.ini`,
  скопированный «чтобы запустилось», несёт в себе чужие драйверы и
  чужие платёжные ключи.
* **Секреты.** Пароли и ключи в файле — только пометки `@secret:`,
  значения в реестре пользователя под DPAPI (шаг 3.2). Файл с открытым
  паролем — сбой акта, а не «потом уберём».
* **Около 450 параметров в одной секции `[General]`**, и у многих
  **своё старшинство относительно базы**: часть читается «файл, затем
  база», часть «база, затем файл», часть только из базы. Поэтому правка
  строки в файле может **ничего не менять**, пока тот же параметр лежит
  в `TMS_INIT_PARAMS`. Справочник всех ключей с их старшинством —
  `docs/cantina-ini.md` в приватном репозитории.

Четыре свойства самого формата, проверенные на живой системе:

| Свойство | Следствие |
|---|---|
| Кодировка **CP1251**, не UTF-8 | редактор, сохранивший файл в UTF-8, портит все русские значения (шапка чека, названия); править в редакторе с явным выбором кодировки или через `cfgtool` владельца |
| При **двух строках с одним именем побеждает первая** | «дописал в конец и не сработало» — ищите тот же ключ выше |
| **Пустое значение равно отсутствию** строки | `Key=` не «выключает» параметр, а отдаёт его базе и значению по умолчанию |
| Имя файла и секции **фиксированы** | `cantina.ini`, `[General]`; переименованный файл касса не увидит |

## 8.5 Как с ним обращаться

1. **Не копировать чужой.** Исходник для стенда —
   [templates/cantina.bench.ini](../templates/cantina.bench.ini) плюс
   значения от владельца (шаг 3.1). Либо файл, который владелец сохранил
   в схему: он приедет с клоном и выкладывается байт в байт
   (`python -m frontarchive ini pull <цель> --out <папка>`, шаг 2.4).
2. **До правки — снимок, после правки — сравнение.** Копия файла с
   датой рядом не нужна: разницу показывает
   `python -m frontarchive settings diff <a> <b> --ini`, а эталон хранится
   в схеме (`ini save`) и в приватном репозитории `schemas/<схема>/`.
3. **После любой правки — три проверки:** `python -m pypos secrets check
   cantina.ini` (все пометки читаются, открытых паролей нет), запуск
   кассы с коротким `selftest.ini` (шаг 3.4) и файл чека виртуального
   принтера (шаг 5). Касса, которая не поднялась после правки ini, — это
   правка, а не продукт.
4. **В акт** попадает `cantina.ini` стенда целиком, с пометками `@secret:`
   вместо значений, и вывод `settings diff` относительно файла владельца.
