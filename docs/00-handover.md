# 0. Что передаёт владелец — и как

Комплект открытый, поэтому всего, что ниже, в нём нет и быть не может.
Без этого стенд не поднять. Получать — **не через чат с ИИ** и не через
файлы в репозитории: пароли идут только в хранилище учётных данных
машины стенда, всё остальное — доступом к приватным хранилищам.

## Обязательно

| Что | Зачем | Как передать |
|---|---|---|
| Доступ к приватному репозиторию `uamenu_experimental_ai` (снимок исходников кассы) либо к `RAD_Tokyo` целиком | собрать кассу, взять `pypos` и `cfgtool` | приглашение в репозиторий GitHub |
| `Sources/Cmp` из `RAD_Tokyo` и установщики компонентов: ODAC (Include\Delphi25\Win32), DevExpress, EurekaLog | без них `UAMenu.cbproj` не соберётся | доступ к `RAD_Tokyo` + лицензии владельца |
| Либо готовый `UAMenu.exe` (Win32/Debug) со всеми DLL из `Win32\Debug` | если сборку не делаем | архив по закрытому каналу |
| Архив фронт-схемы `.fza` (FrontArchive), снятый командой `archive <цель> --exclude MVMS_UNIV_PHOTO` | поднять базу фронта на стенде за 3 минуты | файл ~13 МБ по закрытому каналу; **содержит персональные данные карт — не публиковать** |
| Платформенная схема `UN4PUBLIC` (экспорт или скрипт установки) | без неё в клоне остаются невалидными пакеты, которые зовут `MSG`/`SAY`/`WARN`/`ENVUNIREST` | как есть у владельца |
| Пароли: схема фронта, `SYS` локальной базы (если ставим сами), пользователь DB link к бэк-офису | подключение | **в хранилище учётных данных Windows стенда**, командой `password --file`, файл затирается; см. шаг 1 |
| Имя TNS и адрес бэк-офиса (для DB link `BONUS2019_07.WORLD`) либо явное «бэк-офиса на стенде нет» | обновление цен и витрин | строка в `tnsnames.ora` |
| Проект `FrontArchive` и `License26` из `RAD_Tokyo/Sources` | клон, настройки, лицензия | тот же доступ к `RAD_Tokyo` |

## Желательно

| Что | Зачем |
|---|---|
| Адрес службы лицензий License26 для стенда (или разрешение работать в ознакомительном периоде 30 дней без неё) | акт по лицензии |
| Контрольные данные тестовой схемы: коды товаров, номер дисконтной карты, штрихкод купона, номер карты лояльности | шаги `item`, `card`, `coupon`, `simcard` в сценарии |
| Снимки и журналы прошлого акта владельца | чтобы сравнивать, а не угадывать |

### Контрольные данные, которые уже известны по прошлому акту

Это коды из **тестовой** схемы владельца, не секреты. На другой схеме
они могут не существовать — проверить `select` перед прогоном.

| Что | Значение | Где используется |
|---|---|---|
| Товары | `100516`, `16110`, `69297` | `item,<код>,<кол-во>` |
| Дисконтная карта (тип 6, столовая) | `3902925401573` | `card,<номер>,6` |
| Карта лояльности для имитации | `9131618479561` | `simcard,<номер>,<баланс>,<ставка>` |
| Купон | `280900000001` | `coupon`, `couponinfo` |
| Кассир самотеста | логин `Tolik` | `[Login] User=` в `selftest.ini`; пароль — в реестре |

## Чего владелец передавать не должен

* Пароли в тексте — ни в чате, ни в файле репозитория, ни в `ini`.
* `selftest.ini` с заполненным паролем кассира.
* Архив `.fza` в публичное место: в нём таблицы `MVMS_PERSONS*`,
  `MVMS_CARDS` с данными держателей карт.
