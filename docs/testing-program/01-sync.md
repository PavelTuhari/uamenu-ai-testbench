# 1. Синхронизация данных с бэк-офисом

Касса не хранит ничего локально: справочники и цены — витрины
(материализованные представления `MV*`) в схеме фронта, которые
наполняются из бэк-офиса через DB link `BONUS2019_07.WORLD`; продажи
пишутся прямо в таблицы фронта (`TMDB_COMENZ`, `TMDB_COMENZD`), откуда
бэк-офис их забирает сам. Выгрузки файлами у кассы нет (`dtmod.cpp`,
поиск по `send/export/upload` пуст), поэтому «синхронизация» — это
обновление витрин и проверка, что продажа видна на той стороне.

## 1.1 Обновление справочников из меню

Меню «Работа с базой» / «Lucru cu BD» (`ubdw.cpp`) видно только при
непустом `sys_context('envunirest','DBLink')` и, для кассира,
`ShowMenuDataBase=true`.

- [ ] Открыть «Работа с базой». Снимок `sync-01-bdw`.
- [ ] Переключатель «Обновить справочники с сервера» → «Обновить».
      При `RefreshUnirest=true` касса зовёт `Unirest_Mv_V.refersh_mv`
      (именно с такой опечаткой), иначе `bar$links.setupAllLinks('0')`
      (`dtmod.cpp:1332`).
- [ ] Дождаться конца; записать длительность. Снимок `sync-02-done`.
- [ ] SQL: `select mview_name, last_refresh_date, staleness from user_mviews
      order by last_refresh_date desc` — у витрин свежая дата.

**Ожидается:** без ошибок; `MVPR_PRICES_ACT` и `MVMS_UNIV` обновлены
«сейчас». Если бэк-офиса на стенде нет — касса сообщает об ошибке линка и
**продолжает работать**; это записывается как «DB link не настраивался».

## 1.2 Цена доехала до чека

- [ ] В бэк-офисе (или вручную в `MVPR_PRICES_ACT`, если линка нет) изменить
      цену тестового товара на заметную (например, +1.11).
- [ ] Обновить витрины (1.1) либо `begin unirest_mv_v.refresh_mv_one('MVPR_PRICES_ACT'); end;`.
- [ ] SQL: `select * from vpr_prices where sc = <код>` — новая цена.
- [ ] Новый чек, отсканировать товар — в чеке новая цена. Снимок `sync-03-price`.
- [ ] Вернуть цену назад тем же путём, проверить SQL ещё раз.

**Ожидается:** цена в чеке равна `VPR_PRICES`. Касса цену не кэширует:
изменение видно со следующего сканирования.

## 1.3 Продажа видна на стороне базы

- [ ] Провести чек на два товара, оплатить наличными, напечатать (F12).
- [ ] SQL: `select nrdoc, data, suma, state from tmdb_comenz where nrdoc = <номер чека>`
      и `select sc, cant, pret from tmdb_comenzd where nrdoc = <номер>`.
- [ ] Если бэк-офис подключён — убедиться у него, что чек появился (запрос
      владельца; обычно через те же таблицы по линку с другой стороны).
- [ ] Отменить тестовый чек по правилам раздела 2 либо оставить в тестовой базе
      и записать номер в акт.

**Ожидается:** строки чека в базе совпадают с чеком на виртуальном принтере
по сумме и количеству позиций.

## 1.4 Пересоздание синонимов и чистка заказов

- [ ] «Обновить с пересозданием синонимов» (вариант 2) — только администратор.
      Снимок результата.
- [ ] SQL: `select count(*) from user_objects where status='INVALID'` до и после.
- [ ] «Очистить базу заказов» с датой год назад — на тестовой базе;
      касса зовёт `unirest_util.DELETE_OLD_PERIOD_COMENZ` (`ubdw.cpp:39`).
      Записать, сколько строк ушло.

**Ожидается:** невалидных объектов не стало больше; чистка удаляет только
старше указанной даты.

## 1.5 Старт кассы с недоступным бэк-офисом

- [ ] Сделать линк недоступным (выключить сеть к бэк-офису или временно
      неверный пароль линка на стенде).
- [ ] Запустить кассу с `RefreshOnLoad=true`.
- [ ] Снимок сообщения; касса дошла до главной формы.

**Ожидается:** касса **запускается всегда**. Сообщение об ошибке обновления
— допустимо; невозможность работать — дефект стенда или кассы, в акт.
