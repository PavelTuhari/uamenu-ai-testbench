# 4. Инвентаризация

Отдельной формы нет: инвентаризация — **режим продажной формы**. Он
включается контекстом Oracle `INVENTR` (`main->Inventr = GetContext("INVENTR")`,
`dtmod.cpp:488`), который ставится на стороне базы (для пользователя или
сессии). В этом режиме каждый новый документ создаётся как
`CreateSpecialDoc(InventrDocType)` (`InventrDocType` из ini, по
умолчанию 2; `dtmod.cpp:3347`), а не как чек.

## 4.1 Включить режим

- [ ] Выставить контекст по инструкции владельца (пакет `ENVUNIREST` или
      `dbms_session.set_context`), перезапустить кассу.
- [ ] На форме: при `Inventr=1` появился выбор секции `UnDBSect`
      (`Uhvbb.cpp:183`). Снимок `inv-01-mode`.
- [ ] Клавиши `F5`, `F12`, `Ctrl+R` **не действуют** (`Uhvbb.cpp:2085`).
- [ ] X/Z-отчёт отказывает, если нет `ZXReportByAdminOrInventr`
      (`dtmod.cpp:6430`).

**Ожидается:** касса ясно показывает режим; печать чеков невозможна.

## 4.2 Ввод остатков

- [ ] Выбрать секцию. Сканировать товар с количеством 5; тот же товар ещё
      раз с 2.
- [ ] Весовой товар — через `Ctrl+1` «Взвесить» или вводом веса.
- [ ] Размерный товар (SIZES) — размер и длина спрашиваются как в продаже
      (раздел 8).
- [ ] Закрыть документ принятым способом (как настроено для `InventrDocType`;
      обычно `F11` сохранить).
- [ ] SQL: `select sc, sum(cant) from tmdb_comenzd where nrdoc = <номер> group by sc`
      — 7 и вес, `doc_type` документа = `InventrDocType`.

**Ожидается:** повторное сканирование суммируется или даёт вторую строку —
записать, как именно ведёт себя эта касса (зависит от `Insert_tovar`), и
что бэк-офис из этого ожидает.

## 4.3 Выключить режим

- [ ] Снять контекст, перезапустить.
- [ ] Новый документ снова чек; `F12` печатает.

**Ожидается:** после выхода из режима ни один инвентаризационный документ
не попал в выручку («Итоги») и в Z.
