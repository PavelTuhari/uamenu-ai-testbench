# 3. Приёмка, списание, перемещение, заказ товара: документы с типом

Во фронте это есть — как **чек с типом документа**, сделанный для Alisca
поверх давно существующего режима инвентаризации. Отдельной формы нет:
та же продажная форма, тот же `TMDB_COMENZ`/`TMDB_COMENZD`, но у
документа `DOC_TYPE > 1`, и его **не печатают, а сохраняют**. Бэк-офис
забирает такие документы по `DOC_TYPE` и превращает в приход, списание,
перемещение или заказ поставщику.

## Как устроено (по коду и настройкам Alisca)

| Что | Где |
|---|---|
| Справочник типов | `VMS_SYSS where tip='T' and cod=120`: `cod1` — тип, `denumirea` — название; `1` продажа, `2` инвентаризация, остальные (приёмка, списание, перемещение, заказ) — как заведено у клиента |
| Выбор типа | меню «Выбор операции» (`ShowMenuSelDocType=true`, `fMenu.cpp:2454`) открывает окно `uSelDocType.cpp` с кнопками тачскрин-интерфейса `TSSelDocType` (номер интерфейса — ключ `TSSelDocType`, у Alisca `12`); у кнопки `INTERNAL_CMD='CreateSpecialDoc'`, `ASCII_CODE_STR` = тип, `TXT` = подпись (`TS.cpp:1382`) |
| Создание | `DTM->CreateSpecialDoc(тип, подпись)` (`dtmod.cpp:13463`): `NewBon(тип)` пишет `DOC_TYPE`, касса показывает «Выбран режим: …» и название из `VMS_SYSS` (`dtmod.cpp:3459`); `F11` сохранить включается, `F12` печать выключается |
| Печать запрещена | `fMenu.cpp:345` — «Чек данного типа не поддерживает печать!» |
| Проверка при сохранении | `CheckDocTypeOnSave=true` → `unirest_util.check_doc_type(p_cod)` (`dtmod.cpp:14732`) — правила клиента в его схеме (у Alisca); в `bonuspos_self24` такой процедуры нет |
| Инвентаризация | тот же механизм с `DOC_TYPE = InventrDocType` (по умолчанию 2) по контексту `INVENTR` — раздел 4 |

Настройки Alisca (`cantina_alisca.ini`, `cantina-alisca_pos.ini`):
`GlobalType=Cassa`, `Style=RESTH` или `TS`, `TSSelDocType=12`,
`ShowMenuSelDocType=true`, `CheckDocTypeOnSave=true`. База Alisca —
TNS `alisca`, `alisca_pos`, `alisca_pos2`, `alisca_pos3`.

## 3.1 Есть ли типы документов на стенде

- [ ] SQL: `select cod1, denumirea from vms_syss where tip='T' and cod=120 order by cod1`
      — список типов в акт. На `bonuspos_self24` он **пуст**: там
      интерфейс 13 — выбор карты оплаты, не типов документа.
- [ ] SQL: `select order_id, txt, internal_cmd, ascii_code_str from vts_buttons
      where interface_id = <TSSelDocType> order by order_id` — кнопки с
      `CreateSpecialDoc`.
- [ ] Если ни того, ни другого нет — либо раздел «не применимо», либо
      завести на стенде: строки в `VMS_SYSS` (cod=120) и кнопки интерфейса
      (как у Alisca); сделанное записать в акт.

## 3.2 Приёмка

- [ ] В `cantina.ini`: `ShowMenuSelDocType=true`, `TSSelDocType=<id>`,
      `CheckDocTypeOnSave=true`. Перезапуск.
- [ ] Меню «Выбор операции» → кнопка «Приёмка» (название из базы).
      Снимок `recv-01-seldoc`.
- [ ] На форме предупреждение «Выбран режим: Приёмка»; `F12` не действует,
      `F11` действует.
- [ ] Сканировать два товара, у одного количество 5; весовой — весом.
- [ ] `F12` → сообщение «Чек данного типа не поддерживает печать».
- [ ] `F11` сохранить → при `CheckDocTypeOnSave` сработала `check_doc_type`
      (без ошибки или с понятным отказом — записать).
- [ ] SQL: `select nr_comand, doc_type, state from tmdb_comenz where nr_comand=<номер>`
      — `doc_type` = тип приёмки; `select sc, cant from tmdb_comenzd where nr_comand=<номер>`.
- [ ] «Итоги» и X-отчёт — документ **не** в выручке; на виртуальном
      принтере ничего не появилось.
- [ ] Бэк-офис: документ появился как приход (запрос владельца, по
      `DOC_TYPE` и `NR_COMAND`).

**Ожидается:** документ с нужным `DOC_TYPE`, без печати, без влияния на
кассовую выручку; бэк-офис его видит.

## 3.3 Списание, перемещение, заказ поставщику

Для каждого типа, который есть в `VMS_SYSS cod=120`:

- [ ] «Выбор операции» → тип; предупреждение с названием.
- [ ] Две позиции, `F11`. Снимок `recv-02-<тип>`.
- [ ] SQL: `doc_type` верный; у перемещения — секция/склад назначения, если
      касса его спрашивает (`UnDBSect`, как в инвентаризации).
- [ ] Отмена такого документа `F5` → `state=5`, бэк-офис его не берёт.

## 3.4 Что остаётся в бэк-офисе

- [ ] После обновления витрин (раздел 1) приход виден в кассе остатком и
      ценой — «Информация о товаре».
