# 3. Приёмка товара и специальные документы

**Честно сразу:** отдельной формы приёмки (intrare, recepție, приход) в
кассе **нет** — по исходникам такие слова встречаются только в итогах
кассы («Intrari» — приход денег) и в служебном внесении. Приёмка
товара ведётся в бэк-офисе, касса её только отражает через витрины
(раздел 1).

Что в кассе есть — **специальные документы**: та же продажная форма, но
документ создаётся с другим типом через `DTM->CreateSpecialDoc(DocType)`
(`dtmod.cpp:13463`). Типы и кнопки настраиваются в базе, в интерфейсе
тачскрина `TSSelDocType` (id 13), и показываются пунктом меню «Выбор
операции» (`ShowMenuSelDocType=true`, форма `uSelDocType.cpp`).

## 3.1 Есть ли у этой кассы специальные документы

- [ ] SQL: `select * from vts_buttons where interface_id = 13` (точное
      имя представления — по описанию владельца; это кнопки «Выбор операции»).
- [ ] Если строк нет — раздел «не применимо», в акт: «специальные документы
      не настроены».

## 3.2 Документ прихода, если он настроен

- [ ] Меню «Выбор операции» → кнопка документа прихода. Снимок `recv-01-seldoc`.
- [ ] Набрать две позиции с количеством, как в продаже.
- [ ] Закрыть документ принятым в этом типе способом (F12 или F11).
- [ ] SQL: `select nrdoc, doc_type, state from tmdb_comenz where nrdoc = <номер>`
      — `doc_type` равен типу прихода, не продаже.
- [ ] Итоги кассы («Итоги»/`casa.cpp`) — документ **не** вошёл в выручку.

**Ожидается:** документ записан с нужным `doc_type`; в фискальный принтер
ничего не ушло; в Z-отчёт он не попадает.

## 3.3 Что проверять у бэк-офиса

- [ ] Приход, сделанный в бэк-офисе, после обновления витрин виден в кассе
      остатком («Информация о товаре») и ценой — это и есть «приёмка»
      с точки зрения кассы.
