# 9. Заказы («Заказы» / «Comenzi»)

**Что это на самом деле.** Окно «Заказы» (`order.cpp`, `Tforder`,
`DTM->load_forder()`, `dtmod.cpp:883`) — заказы столовой, ресторана и
доставки: столы, официанты, разделение счёта. Данные —
`VMDB_COMENZ_RESTAURANT` и `VMDB_COMENZD`. Поведение зависит от `Style`
(`DOSTAVKA`, `PRODZACAZ`, `RESTH`, `TS`).

**Заказа товара наружу — поставщику или в бэк-офис — в кассе нет.** Такие
заказы делаются в бэк-офисе; касса может только передать клиента в
бухгалтерию (`unirest_link_util.send_client_buh`, `order.cpp:2031`). Если
«заказ наружу» нужен на кассе, это новая задача; в акт — «не реализовано».

## 9.1 Заказ

- [ ] Меню «Заказы». При `PinOfficiant=true` — PIN официанта. Снимок `ord-01-list`.
- [ ] `Insert` → новый заказ (стол, официант, число гостей).
- [ ] Добавить позиции (`addAction1`, `order.cpp:473`) — три блюда, одно с
      количеством 2.
- [ ] SQL: `select * from vmdb_comenzd where nr_comand = <номер>` — три строки.

## 9.2 Изменения

- [ ] Дубликат заказа (`yunirest.Dubl`) → новый номер, те же позиции.
- [ ] Дисконтная карта к заказу (`disc_unirest.pay_disc_card`) → скидка в итоге.
- [ ] Разделить счёт (`yunirest.complet_razbiv`) → два счёта на тех же гостей.
      Снимок `ord-02-split`.

## 9.3 Закрытие

- [ ] «Закрыть» → `close_comand` (`order.cpp:855`): `yunirest.can_close`
      разрешил, `complet_tmdb_beg` создал чек, `throw_off_order` снял заказ.
- [ ] Оплатить чек (раздел 5), напечатать → файл чека с позициями заказа.
- [ ] Заказ, который закрыть нельзя (например, неоплаченный долг) → отказ с
      причиной от `can_close`.

**Ожидается:** закрытый заказ превращается ровно в один чек; открытых
копий не остаётся.

## 9.4 Доставка (`Style=DOSTAVKA`)

- [ ] Новый клиент из заказа → «отправить в бухгалтерию» → клиент есть в
      бэк-офисе (запрос владельца).
- [ ] Время оплаты и адрес в заказе печатаются в чеке.
