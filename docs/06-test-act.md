# 6. Акт тестирования кассы

Акт — это не «запустили, работает». Это файл, который можно переслать:
сценарий, журнал прогона, снимки, таблица «ожидалось / получено» по
каждому пункту и отдельный список того, что не проверяли. Так делались
акты владельца; этот шаг повторяет тот же порядок.

## 6.1 Порядок

1. **Стенд готов** (шаги 1–5 пройдены, `check-prereqs.ps1` зелёный).
2. **Сценарий** — [templates/selftest.bench.ini](../templates/selftest.bench.ini):
   полный цикл продажи. Контрольные данные (коды товаров, карта, купон)
   заменить на те, что есть в вашей схеме — проверить `select` заранее.
3. **Прогон**: положить `selftest.ini` рядом с `UAMenu.exe`, запустить
   `UAMenu.exe`, дождаться закрытия (`CloseAfter=1`). Ничего не трогать
   руками во время прогона.
4. **Собрать**: каталог `SelfTest\<дата-время>\` целиком, `license.log`,
   свежие файлы из `VirtualCheckPrinter\`, вывод команд из шагов 2 и 4.
5. **Заполнить таблицу** ниже — по журналу и снимкам, не по памяти.
6. **Проверить журналы на секреты**: поиском значения пароля кассира и
   схемы по `selftest.log` и `license.log`. Найдено — акт не принимается.
7. **Убрать за собой**: проверочные цены возвращены, пробные чеки
   отменены (`KeepOpenCheck=0` делает это сам), временные файлы удалены.

## 6.3 Что прислать

Один каталог (или архив) с подкаталогами:

```
act-<дата>/
  README.md            эта таблица с заполненной колонкой "Получено" + раздел "Не проверяли"
  selftest.ini         сценарий, которым гоняли (пароли - пометками)
  selftest/            журнал и снимки прогона как есть
  receipts/            VPCheck_*.txt
  license.log
  commands.txt         команды шагов 2 и 4 и их вывод
```

Раздел **«Не проверяли»** обязателен. В прошлом акте владельца он
выглядел так: реальные фискальные устройства не подключались; DB link к
бэк-офису на стенде не было, витрины статичны; отбор прайс-листа по
магазину не разбирался; телефон и сборка APK не проверялись.

## 6.4 Что считать сбоем

* Касса не запустилась или зависла — **сбой стенда**, разбирать до акта.
* Шаг сценария с ошибкой в журнале (`шаг …: …`) — сбой пункта; в
  таблицу — текст из журнала.
* Значение пароля в любом файле акта — сбой акта целиком.
* Расхождение цены в чеке и в `VPR_PRICES` — сбой пункта 4; обычно это
  неверный `PL_ID` или не обновлённая витрина (шаг 4).
* `шаг print пропущен: текущий принтер не виртуальный` — в базе
  `FiscalPrinter` перекрывает файл (шаг 5.1).

## 6.5 Как это делалось у владельца

Для сравнения — цифры прошлого акта (сентябрь 2026): касса собрана
`msbuild` без ошибок; самотест — полный цикл с картой, купоном и
мультиоплатой, 39 шагов; акт лицензирования — чистый запуск (талон за 5
секунд) и занятое место (`409`, предупреждение, окно активации);
пароли перенесены в реестр, самотест вошёл с ними, в журналах значений
нет; клон фронта — 170 таблиц, 1 320 644 строки, расхождений 0.
