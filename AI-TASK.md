# Задание ИИ: поднять Oracle Database Free и кассовую схему локально

Ты — ИИ-агент (или инженер) на компьютере с Windows 10/11 x64. Твоя
задача: локально поставить **Oracle Database Free** (это бесплатная
локальная база с oracle.com; не путать с облачным тарифом «Always Free»),
импортировать в неё подготовленную копию кассовой схемы и подтвердить,
что всё работает. Касса UAMenu потом будет работать с этой базой.

Почти всё за тебя делает один скрипт. Твоя работа — запустить его,
прочитать его итог и, если он упал, починить **только упавший шаг**.

## Экономь токены

* Не читай исходники скрипта целиком «на всякий случай». Запусти — он
  печатает, что сделал и где упал, и подсказывает, что смотреть.
* Не пересказывай вывод. Нужна только последняя строка каждого шага и
  строка `СБОЙ`, если есть.
* После исправления перезапускай с `--skip-<сделанные шаги>`: скачанное
  не скачивается заново, поставленное не ставится.
* Не открывай журнал установки (`install.log`, 700 КБ) целиком: ищи в нём
  `SEVERE`, `Return value 3`, `error status`.

## Что нужно до старта

| Что | Откуда |
|---|---|
| Python 3.12 и `pip install oracledb keyring flask cryptography` | python.org |
| Этот комплект, распакованный целиком | github.com/PavelTuhari/uamenu-ai-testbench |
| Каталог `Sources/FrontArchive` из приватного репозитория владельца (`RAD_Tokyo`, ветка `feature/front-archive`) | владелец даёт доступ |
| Архив кассовой схемы `*.fza` (~13 МБ) | владелец передаёт закрытым каналом; **не публиковать**, в нём данные держателей карт |
| Права администратора на машине — установщик спросит через UAC | человек рядом нажимает «Да» |
| 20 ГБ на диске и около 40 минут (скачать 1,4 ГБ, поставить 15–25 мин, импорт 3 мин) | |

Пароли ты **не вводишь и не видишь**: `SYS` создаётся случайным и ложится
в хранилище учётных данных Windows, пароль схемы клона — туда же.

## Команда

```bat
python scripts\bootstrap_oracle_free.py ^
    --work D:\OracleFree ^
    --install-dir D:\Oracle26ai\product\26ai ^
    --port 1522 ^
    --archive D:\handover\front.fza ^
    --frontarchive D:\RAD_Tokyo\Sources\FrontArchive
```

Диски и каталоги — любые локальные (не сетевые). Порт **1522**, не 1521:
установщик считает 1521 занятым, если видит хоть одно соединение с таким
номером на машине.

Скрипт идёт по шагам `url → download → extract → client → install →
restore → verify`, каждый пишет итог. Последняя строка при успехе:
`готово: база и схема на месте`.

## Если упало — что обычно и что делать

| Шаг | Что печатает | Причина | Что делать |
|---|---|---|---|
| `url` | нет ссылки на Windows-дистрибутив | Oracle переделал страницу | открыть https://www.oracle.com/database/free/get-started/ , взять ссылку на `...windows.x64.zip`, передать `--url` |
| `download` | размер не сошёлся | обрыв | повторить — докачает |
| `extract` | setup.exe в подкаталоге | другая раскладка архива | передать `--work <тот каталог>` и `--skip-url --skip-download --skip-extract` |
| `client` | Instant Client не скачался | ссылка oracle.com изменилась | скачать basic zip вручную, распаковать в `C:\oracle\instantclient`, задать `ORACLE_CLIENT_DIR` |
| `install` | окно UAC отклонено | никто не нажал «Да» | повторить с `--skip-url --skip-download --skip-extract --skip-client` |
| `install` | служба не работает | смотри `install-status.txt` и `install.log` в `--work` | ниже четыре известные грабли |
| `restore` | схема не пуста | старый клон | добавить `--wipe` |
| `restore` | нет пароля SYS в хранилище | установка не дошла до записи пароля | повторить шаг `install` (он перезапишет пароль) |
| `restore` | `ORA-12899` или ошибки DDL | не наш случай: FrontArchive ставит `NLS_LENGTH_SEMANTICS=CHAR` сам; если всё же — см. вывод, сообщить владельцу |
| `verify` | невалидных объектов 57 | нормально для чистого сервера: нет платформенной схемы `UN4PUBLIC` | не ошибка; описано в `docs/02-database.md` |

Четыре грабли установщика Oracle Free, из-за которых скрипт устроен так,
а не через `setup.exe`:

1. `setup.exe` ставит пакет VC++, тот просит перезагрузку, и `setup.exe`
   молча выходит с кодом 0, ничего не поставив → скрипт зовёт `msiexec`
   напрямую.
2. `Folder is not secure` — проверяется вся цепочка каталогов назначения
   → цепочка создаётся закрытой (только `SYSTEM` и администраторы).
3. `SEVERE: ... TNS_ADMIN` — при заданной системной `TNS_ADMIN`
   установщик отказывается → снимается на время установки и возвращается.
4. `port ... not available` при свободном 1521 → порт 1522.

Если установщик всё равно падает на чём-то новом — это и есть тот нюанс,
ради которого здесь ты, а не только скрипт: прочитать `SEVERE`-строку,
поправить (чаще всего — права каталога, переменные окружения, занятый
порт), повторить шаг. Правки в скрипт — приветствуются, с комментарием,
что именно случилось.

## Что ожидается в итоге

```
служба OracleServiceFREE: RUNNING, порт 1522 слушается
restore: таблиц 170, строк 1 320 644, расхождений 0, ошибок DDL 0
невалидных объектов: 57 (без UN4PUBLIC) либо 9 (с UN4PUBLIC) - с перечнем причин
describe free-front: Oracle AI Database 26ai Free ..., кодировка AL32UTF8
ini show free-front: cantina.ini, selftest.ini в пакете CANTINA_INI
```

Цифры — для архива владельца на сентябрь 2026; у другого архива будут
свои, важно «расхождений 0».

## Что прислать владельцу

1. Последние 15 строк вывода скрипта.
2. Если что-то чинил — что именно и почему (две строки на случай).
3. Чего не делал: например, «UAC нажимал человек», «UN4PUBLIC не ставил».

Дальше — `docs/08-uamenu-install.md`: положить кассу отдельной папкой
рядом с UnaDesktop (не в `Program Files`, не внутрь UnaDesktop) и
прочитать, почему `cantina.ini` нельзя брать чужой; затем
`docs/03-till-config.md`: настроить кассу на эту базу и снять акт
(`docs/06-test-act.md`).
